# AMD BC-250 configuration and builds

OptiScaler recognizes AMD BC-250 / GFX1013 by PCI vendor/device ID `1002:13FE` and
selects the FSR 4 **INT8** model when detecting D3D12 capabilities. The PCI-ID
match takes precedence over Wine's ASIC-family information and works without a
matching entry in the bundled GPU database. Explicit `Fsr4GpuSupport` and
`Fsr4Model` overrides retain their existing behavior.

Running FSR 4 still requires a compatible driver stack and an FSR 4 implementation
containing the INT8 model. This change enables GPU recognition and configuration;
it does not provide driver optimizations or FP8 support.

## Linux / Proton setup

1. Install your BC-250-compatible RADV driver separately. The sibling
   [bc250-fsr4 project](https://github.com/dmorazasanchez/bc250-fsr4/tree/v3)
   documents its per-user V3 installation and requirements.
2. Install OptiScaler using the normal Linux setup instructions. To use the
   optional profile, back up your existing `OptiScaler.ini`, then copy
   `profiles/BC250.ini` into the game executable folder as `OptiScaler.ini`.
   Alternatively, merge the profile's sections into your existing INI.
3. Install your compatible FSR 4 INT8 DLL separately in the `OptiScaler` library
   folder. The build package includes the upstream SDK runtime files; it does
   not guarantee that an FSR 4 INT8 model is available. FSR 4.1.1+ modules that
   contain multiple models support the `Fsr4Model` selector.
4. For the sibling project's V3 driver and `version.dll` injection, use:

   ```text
   VK_DRIVER_FILES="$HOME/.local/share/bc250-fsr4/v3/radv-bc250-fsr4-v3.json" WINEDLLOVERRIDES="version=n,b" %command%
   ```

   Use your actual ICD path and injection filename. Preserve any other DLL
   overrides your game needs.
5. Check `OptiScaler.log` for `Recognized AMD BC-250 (GFX1013)` and
   `Upscaler support - fsr4: int8`. Confirm the active FSR version/model in the
   overlay; recognition alone does not verify that FSR 4 ran successfully.

The profile selects `Dx12Upscaler=ffx`, `UpscalerIndex=0`,
`Fsr4GpuSupport=2` (INT8 capability), and `Fsr4Model=1` (INT8 model).
It disables frame generation for an initial upscaling-only setup and enables
Info-level file logging. Other options use OptiScaler's defaults. Capability and
model use different numeric enums; do not interchange their values.

The sibling OptiScaler Client currently writes the older `Fsr4ForceModel` and
`Fsr4ForceEnableInt8` keys. This profile uses this checkout's current keys.

## Builds

The **Build and package** GitHub Actions workflow runs on pushes to any branch and
pull requests to `master`, and supports **Actions → Build and package → Run workflow**.
It checks out the pinned submodules and builds Release x64 with Visual Studio
2022 / MSVC v143. No signing secrets or environment configuration are required.

Download the `OptiScaler-BC250-<commit>` artifact from a successful run. Extract
the artifact, then extract the inner versioned ZIP into the game folder. The ZIP
includes the DLL, runtime files, setup scripts, optional profile, these
instructions, and license files. The main packaged `OptiScaler.ini` retains
upstream defaults. A `.sha256` checksum accompanies the ZIP. Failed builds upload
an MSBuild binary log. Builds are unsigned; the workflow does not publish releases.

For the same build locally, install Visual Studio 2022's Desktop development
with C++ workload and a Windows SDK, then run in a Developer PowerShell:

```powershell
git submodule update --init --recursive
./scripts/build.ps1
```

The ZIP and checksum are written to `artifacts/`. OptiScaler is a Windows DLL
used through Proton/Wine on Linux; compilation requires a Windows build host.
