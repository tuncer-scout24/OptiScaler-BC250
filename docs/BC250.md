# AMD BC-250 configuration and builds

These are unofficial, independently maintained BC250 builds of
[OptiScaler](https://github.com/optiscaler/OptiScaler), developed by the upstream
OptiScaler team and contributors. This fork adds limited BC250 compatibility,
configuration, and packaging changes. Please report issues with these builds in
[this repository](https://github.com/tuncer-scout24/OptiScaler-BC250/issues).

OptiScaler recognizes AMD BC-250 / GFX1013 by PCI vendor/device ID `1002:13FE` and
selects the FSR 4 **INT8** model when detecting D3D12 capabilities. The PCI-ID
match takes precedence over Wine's ASIC-family information and works without a
matching entry in the bundled GPU database. Explicit `Fsr4GpuSupport` and
`Fsr4Model` overrides retain their existing behavior.

Running FSR 4 still requires a compatible driver stack. Starting with Alpha 2,
the package includes the supplied AMD FSR 4 provider DLLs in `OptiScaler/`:
`amdxcffx64.dll` for DirectX 12 and `amdvkffx64.dll` for Vulkan. Both are x64
version `2.4.0.4370`. See `docs/FSR4-providers.md` in the package for their hashes.
This change enables GPU recognition and configuration; it does not provide
driver optimizations or FP8 support.

## Linux / Proton setup

1. Install your BC-250-compatible RADV driver separately. The sibling
   [bc250-fsr4 project](https://github.com/dmorazasanchez/bc250-fsr4/tree/v3)
   documents its per-user V3 installation and requirements.
2. Install OptiScaler using the normal Linux setup instructions. To use the
   optional profile, back up your existing `OptiScaler.ini`, then copy
   `profiles/BC250.ini` into the game executable folder as `OptiScaler.ini`.
   Alternatively, merge the profile's sections into your existing INI.
3. Extract the entire package, including the `OptiScaler` library folder. Alpha 2
   includes `OptiScaler/amdxcffx64.dll` and `OptiScaler/amdvkffx64.dll` alongside
   the upstream SDK runtime files. Leave these filenames unchanged: OptiScaler's
   driver-provider loader searches this directory for them. `Fsr4Model` selects
   the INT8 model from providers that contain multiple models.
4. For the sibling project's V3 driver and `version.dll` injection, use:

   ```text
   VK_DRIVER_FILES="$HOME/.local/share/bc250-fsr4/v3/radv-bc250-fsr4-v3.json" WINEDLLOVERRIDES="version=n,b" %command%
   ```

   Use your actual ICD path and injection filename. Preserve any other DLL
   overrides your game needs.
5. Check `OptiScaler.log` for `Recognized AMD BC-250 (GFX1013)` and
   `Upscaler support - fsr4: int8`. Confirm the active FSR version/model in the
   overlay; recognition alone does not verify that FSR 4 ran successfully.

The profile selects `Dx12Upscaler=ffx`, `UpscalerIndex=0`,
`Fsr4GpuSupport=2` (INT8 capability), and `Fsr4Model=1` (INT8 model).
It disables frame generation for an initial upscaling-only setup and enables
Info-level file logging. Other options use OptiScaler's defaults. Capability and
model use different numeric enums; do not interchange their values.

The sibling OptiScaler Client currently writes the older `Fsr4ForceModel` and
`Fsr4ForceEnableInt8` keys. This profile uses this checkout's current keys.

## Removal

Run `remove_optiscaler.sh --remove=y` on Linux, or `Remove_OptiScaler.bat` on
Windows, from the game installation. These scripts are generated by setup and
operate on their own directory even when launched from another working directory.

The updated removers delete the complete `OptiScaler/` runtime tree, including
both AMD provider DLLs and nested SDK, plugin, and license folders. They also
remove the shipped BC250 profile, documentation, configuration, and logs.
Unrelated files in shared `docs/`, `profiles/`, and `Licenses/` folders are retained.
The project's GPL license is now packaged as `Licenses/OptiScaler_LICENSE.txt`;
the old root `LICENSE` is removed only if it matches the GPL text shipped in
Alpha 1/2. Other game license files are retained.

Existing generated removers do not update themselves: use setup from a build
containing this fix to generate the updated remover. Remove the OptiScaler DLL
override from your game's launch options after uninstalling.

## Builds

The **Build and package** GitHub Actions workflow runs on pushes to any branch and
pull requests to `master`, and supports **Actions → Build and package → Run workflow**.
It checks out the pinned submodules and builds Release x64 with Visual Studio
2022 / MSVC v143. No signing secrets or environment configuration are required.

For a directly usable single ZIP, download `OptiScaler_BC250_Alpha2.zip` from the
[Alpha 2 release](https://github.com/tuncer-scout24/OptiScaler-BC250/releases/tag/bc250-alpha.2)
and extract it once into the game folder. The root contains `OptiScaler.dll`,
`OptiScaler.ini`, and setup scripts; provider DLLs are under `OptiScaler/`.

Alternatively, download the `.zip` artifact from a successful workflow run and
extract it once into the game folder. The checksum is a separate artifact; the
runtime ZIP is uploaded directly, without an extra artifact ZIP wrapper. The ZIP
includes the DLL, runtime files, setup scripts, optional profile, these
instructions, and license files. The main packaged `OptiScaler.ini` retains
upstream defaults. A `.sha256` checksum accompanies the ZIP. Failed builds upload
an MSBuild binary log. Builds are unsigned.

Pushing a tag named `bc250-alpha.N` builds the tagged commit, verifies the runtime
ZIP and checksum, and publishes those exact artifacts as a GitHub prerelease.
Branch and pull-request builds only upload artifacts. For example, after
committing the changes for the next alpha:

```bash
git tag bc250-alpha.3
git push origin bc250-alpha.3
```

The release contains `OptiScaler_BC250_Alpha3.zip` and its `.sha256` file, with
no manual downloading or re-uploading required.

For the same build locally, install Visual Studio 2022's Desktop development
with C++ workload and a Windows SDK, then run in a Developer PowerShell:

```powershell
git submodule update --init --recursive
./scripts/build.ps1
# To use the release asset name locally:
./scripts/build.ps1 -ReleaseTag bc250-alpha.3
```

The ZIP and checksum are written to `artifacts/`. OptiScaler is a Windows DLL
used through Proton/Wine on Linux; compilation requires a Windows build host.
